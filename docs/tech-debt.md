# Техдолг (из ревью M1)

Перенесено из SDD-леджера M1 при закрытии вехи (2026-09-07). Триаж финального ревьюера.

## К M2 (WiFi-менеджер переписывает net.c — закроется по ходу)
- net.c: нет проверок `esp_event_handler_register`; реконнект без backoff; SNTP не стартует, если IP пришёл после 15с таймаута (`net_start_sta` уже вернул TIMEOUT) — лечится ребутом.
- CI с пустыми dev-кредами не линкует net-путь (компилятор выкидывает по `strlen("")==0`).
- board_hal: `esp_lcd_*` в REQUIRES вместо PRIV_REQUIRES (гигиена).
- hal_input_c3.c: возвраты `iot_knob/iot_button register_cb` не проверяются; утечка knob-хендла при частичном отказе.
- Heap-мониторинг: в приёмке M1 проверен только «без ребутов 10 мин»; числовой free-heap появится в `/api/status` (спека).

## К M3 (перед ростом числа экранов)
- carousel.c: магическая `8` (завести CAROUSEL_MAX + bounds-check в init/set_enabled).
- Стартовая яркость 80 задублирована в hal_display_c3.c и screen_clock.c.
- Форматирование времени внутри tick_cb — извлечь в хост-тестируемый модуль, когда усложнится.
- UX: SHORT приходит ~400мс после отпускания (плата за double-click в iot_button) — учесть в семантике действий.

## К M3 (из финального ревью M2)
- Ретрай STA из AP-fallback: после блэкаута роутер поднимается позже устройства -> STA-таймаут 15с -> AP навсегда; нужен периодический ретрай (1-5 мин) или авторебут при provisioned+AP.
- RESTART_DELAY_MS=1500 в wifi_mgr.c: телефон может не успеть увидеть «Готово» (канал-хоп + ребут); если приёмка подтвердит — поднять до 4-5с.
- Смена web_pass в веб-морде (сейчас = паролю AP с экрана).
- Не-UTF8 SSID (cp1251-роутеры) не подключить через портал; нужен ручной ввод SSID.
- Гонки s_state/web_notify без мьютекса (исходы благоприятные, но закрыть); залипание «trying» при POST в окне restart; scan_json: ошибка скана неотличима от «сетей нет»; poll() портала без таймаута.
- Из ре-ревью фикс-волны M2 (все — на сверхредком пути отказа записи NVS, парковано осознанно):
  окно кнопки сброса добавляет безусловные 2с к каждой загрузке (перенести после ui_init);
  частичная запись wifi_ssid без wifi_pass не откатывается (settings_erase_key в ветке ошибки);
  после «failed to save settings» повторные попытки из портала залипают в trying до передёргивания питания (гейт s_state=WSM_STA_OK) — чинить вместе с мьютексом s_state.

## Из порта на S3 (M2.5)
- Тачскрин работает, координаты логируются, но UX отсутствует (кнопки/свайпы будут в M3+).
- AMOLED burn-in — нужна заставка с периодическим смещением контента и/или dimming для долгоживущих UI-элементов; добавить в бэклог UI.
- LCD_BUF_LINES=20 — первое значение, при котором дисплей стабилен; точная граница минимума не измерена (ниже может быть нестабильность).
- I2C-read тачскрина в LVGL-таске блокирует (унаследовано из esp_lvgl_port); для S3 это некритично (466×466, 60 FPS), но для высокоё частоты кадров нужен перенос в отдельный таск с посл-ю.
- esp_lcd_touch инициализируется единожды в hal_touch_s3.c, шина I2C (SDA=1/SCL=3) живёт локально; если позже добавить ещё одно I2C-устройство на этих пинах, вынести создание шины в отдельный hal_i2c-модуль с общим хэндлом вместо дублирования `i2c_new_master_bus`.

## Мелочь без срока
- net.c: нет явного `freertos/event_groups.h` (живёт на транзитивных инклудах).
- ui.c: дефолтный экран LVGL после `lv_screen_load` — сирота (~сотни байт, однократно).
- CI: `esp-idf-ci-action@v1` — плавающий тег (можно запиновать по SHA).
- hal_touch_s3.c: I2C-шина (SDA=1/SCL=3) создаётся и живёт внутри `hal_touch_init()`, хэндл никому больше не доступен; если появится второе I2C-устройство на этих пинах, вынести создание шины в отдельный `hal_i2c`-модуль с общим хэндлом вместо второго `i2c_new_master_bus`.

# knobos — своя прошивка для круглой крутилки (продукт)

Дата: 2026-09-07
Статус: дизайн утверждён, ждёт плана реализации
Предыстория: этап 1 — ESPHome-пульт HA ([2026-07-31-viewe-knob-ha-remote-design.md](2026-07-31-viewe-knob-ha-remote-design.md)); корпус готов, цель — устройство на продажу.

## Железо

- Целевая плата v1: VIEWE UEDX24240013-MD50E — ESP32-C3 (4MB flash, 400KB RAM,
  без PSRAM), круглый IPS 1.28" 240×240 GC9A01A, энкодер-кольцо + кнопка,
  без тача. USB HID невозможен (у C3 только USB-Serial/JTAG).
- Прицел на будущее: S3-версии крутилок VIEWE. Весь доступ к железу — через
  HAL-интерфейс; портирование = новая реализация HAL, не переписывание.
- Отправная точка драйверов: официальные ESP-IDF примеры VIEWESMART для этой
  платы (github.com/VIEWESMART/ESP32-IDF, examples/1.3inch).

## Позиционирование

Автономное настольное устройство: часы, погода, таймер. Home Assistant —
опция, добавляющая экран дел (и в будущем больше). Покупателю не нужен
ни HA, ни MQTT-брокер, ни облако производителя.

## Стек и бюджеты

- ESP-IDF 5.x, LVGL 9, FreeRTOS.
- Разметка flash 4MB: NVS + 2 OTA-слота по ~1.5MB + LittleFS ~0.7MB
  (настройки-файлы, кэш погоды, пользовательский фон).
- Жёсткий бюджет прошивки: ≤1.5MB (следить за шрифтами и cert bundle).
- Три задачи FreeRTOS: UI (LVGL), network (погода/HA/SNTP), OTA.
  Связь через esp_event; сеть никогда не блокирует UI.

## Структура репозитория `~/homeplace/knobos`

- `components/hal/` — интерфейс дисплей/энкодер/кнопка/подсветка + реализация C3
- `components/core/` — настройки (NVS), WiFi-менеджер (STA/AP), OTA-менеджер, event bus
- `components/services/` — weather (Open-Meteo), ha_client (REST), timekeeper (SNTP+TZ)
- `components/ui/` — LVGL, карусель, экраны (файл на экран)
- `components/web/` — HTTP-сервер, embedded-страница (gzip), REST API
- `main/` — только композиция
- `test/host/` — хост-юниты (CMake+Unity) для чистой логики
- `.github/workflows/` — CI: сборка PR; по тегу — релиз с firmware.bin + manifest.json

## Экраны и UX

Глобально: долгое нажатие (>0.6с) — следующий экран карусели.

| Экран | Вращение | Короткое нажатие | Двойной клик |
|---|---|---|---|
| Часы+погода | яркость подсветки | — | — |
| Дела (только с HA) | скролл списка | отметить выполненным | — |
| Таймер | минуты (таймер, стоя) / выбор режима (в селекторе) | старт/пауза | сброс / вход в выбор режима |
| Настройки | скролл строк | действие строки | — |

- **Часы+погода:** большое время, дата; иконка погоды по WMO-коду
  (солнце/облачно/тучи/дождь/снег/гроза/туман — набор LVGL-изображений),
  температура сейчас + мин/макс дня.
- **Дела:** задачи на сегодня из HA `todo.*` (сущности выбираются в веб-морде);
  без настроенного HA экран исключается из карусели.
- **Таймер:** режимы таймер/секундомер/pomodoro (25/5, счётчик циклов, v1 без
  настройки длительностей). Прогресс — дуга по краю экрана; финал — мигание.
- **Настройки:** версия ПО, репозиторий обновлений, SSID/IP, статус HA,
  «Проверить обновления» (нажатие: проверка → ещё нажатие: установить),
  «Сброс WiFi».

## Онбординг (первое включение / сброс WiFi)

1. Нет сохранённых WiFi-кредов → AP `Knob-XXXX` (XXXX из MAC), пароль
   per-device; на экране устройства SSID + пароль + QR.
2. Captive portal (DNS-перехват): мастер — скан сетей → пароль → подключение.
3. Успех STA → креды в NVS, перезагрузка в рабочий режим.
   Провал → возврат в AP с сообщением об ошибке.
4. Всегда доступен выход: «Сброс WiFi» в настройках на самом устройстве.

## OTA из GitHub Releases

- В релизе: `firmware.bin` + `manifest.json` {version (semver), url, sha256}.
- Проверка: раз в сутки + вручную (экран настроек / веб-морда).
- Накат: скачивание во второй слот → проверка SHA256 → пометка загрузочным →
  ребут → health-check 60с (UI поднялся, WiFi ок) → подтверждение;
  иначе автооткат esp_ota.
- Дефолтный репозиторий зашит при сборке, переопределяется в веб-морде (NVS).
- Понижение версии не ставится (кроме явного «force» в веб-морде).
- HTTPS через esp_crt_bundle; редиректы GitHub → S3 поддерживаются
  esp_http_client.
- CI по тегу `v*` собирает и публикует релиз — конвейер обновлений.

## Веб-морда

Одна embedded-страница (vanilla JS, цель ~30KB gzip):
- статус (версия, uptime, WiFi, свежесть погоды/HA);
- WiFi (смена сети);
- погода: поиск города через геокодинг Open-Meteo → lat/lon в настройки;
- HA: URL + long-lived token, выбор todo-сущностей, «проверить связь»;
- обновления: репозиторий, «проверить сейчас», журнал последнего OTA;
- кастомизация: загрузка фона циферблата (PNG 240×240 в LittleFS);
- смена пароля веб-морды.

Защита: HTTP basic auth; пароль по умолчанию = пароль AP устройства
(на экране/наклейке), меняется. API: `GET /api/status`, `GET /api/wifi/scan`,
`POST /api/wifi`, `POST /api/settings`, `POST /api/ota/check`,
`POST /api/ota/install`, `POST /api/files/background`.

## Данные и офлайн

- Время: SNTP + таймзона (POSIX TZ, задаётся с городом); RTC тикает без сети.
- Погода: Open-Meteo (без ключа), обновление каждые 30 мин, кэш последнего
  ответа в LittleFS, на экране возраст данных при устаревании.
- HA: опрос todo раз в 5 мин + по действию; отметка выполнения —
  `todo.update_item` через REST.
- Потеря WiFi: иконка на всех экранах, всё остальное живёт на кэше.
- Повреждённые настройки → дефолты + пометка в веб-морде; OTA не может
  окирпичить устройство (двухслотность + rollback).

## Критерии успеха v1

1. Новое устройство из коробки: AP → мастер → WiFi покупателя → часы с
   погодой без единого действия за пределами телефона.
2. Релиз в GitHub → устройство само предлагает обновление, накатывает и
   переживает неудачную прошивку откатом.
3. Экран дел работает у владельца с HA и корректно отсутствует без HA.
4. Устройство месяц живёт без перезагрузки (нет утечек heap — мониторинг
   free heap в /api/status).
